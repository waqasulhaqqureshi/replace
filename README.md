# DeepSeek V4.1-Flash · 1017 — Motion Graphics System

A complete motion-graphics system built on top of `Deepseek strikes again.mp4` (1280×720,
30 fps, **27:21**), covering all four requested deliverables:

1. a measured **timestamp scene index** for the whole runtime,
2. a **render pipeline** that burns overlays into the existing video,
3. a **60 fps React/Framer/GSAP player** that reacts live to video timestamps,
4. a **new 48-second film** with storyboard, style guide and an original score.

The spine of the whole thing is one file — [`graphics/timeline.json`](graphics/timeline.json) —
which every renderer and the web player read. Nothing is hand-copied between deliverables.

## What was actually in the video

Analysed at 1 fps (1,641 frames) with ffmpeg scene scoring, audio envelope extraction and
per-frame colour/motion statistics. Key findings that drove the design:

- **It is not 30 minutes.** The file is 27:21; the index covers all of it in six 5-minute blocks.
- **777 hard cuts** — a fast, montage-style edit. Overlays therefore never use long animated
  intros; enter 460 ms / exit 340 ms is the house standard.
- **Only two silences** in 27 minutes (0.96 s at `08:11`, 1.14 s at `10:56`). Narration is
  continuous, so every graphic is narration-locked rather than music-locked.
- **Uniformly blue plates** (210–240° dominant hue in every block). The accent system leads with
  cyan, lime and amber so graphics read *against* the plate, not into it.
- **~50–70% of some blocks are frozen UI screens** — the reason 8 ticker rails and a live canvas
  waveform exist: static sections need motion, not more panels.
- **The source already animates one section itself** (`02:50–03:50`, "The shadow that measured
  the Earth"). Those beats are annotated in the margin instead of restyled — the one place where
  the graphics deliberately stay quiet.

## Quick start

```bash
make                  # list every target
make all              # analyse → timeline → docs → ass → consistency checks
make player           # live 60 fps player on :5173
make render-intro     # the 48 s film
make render-highlights  # 60 fps burn-in of the six key windows
```

Or step by step:

```bash
# ── live player ────────────────────────────────────────────────────────────
cd web && npm install && npm run dev      # → http://localhost:5173

# ── burn overlays into the 27-minute source ────────────────────────────────
python3 scripts/render_overlay.py --out out/deepseek_overlay_full.mp4

# highlights only (6 windows, 60 fps overlay motion) — what ships in render/
python3 scripts/render_overlay.py \
  --segments "0-62,150-240,676-762,1244-1300,1395-1500,1500-1585" \
  --render-fps 60 --out render/deepseek_overlay_highlights.mp4

# ── pure-FFmpeg path (no Python at render time) ────────────────────────────
python3 scripts/make_ffmpeg_ass.py        # → render/overlay.ass + scripts/ffmpeg_overlay.sh
bash scripts/ffmpeg_overlay.sh 0 60 out/clip_0_60.mp4

# ── new 48 s film ─────────────────────────────────────────────────────────
python3 scripts/synth_audio.py            # original score (no licensed music)
python3 scripts/render_intro.py --out render/intro_1017.mp4
```

Regenerate the analysis and docs at any time:

```bash
python3 scripts/analyze_video.py   # measurements  → analysis/metrics.json
python3 scripts/build_timeline.py  # decisions     → graphics/timeline.json
python3 scripts/make_docs.py       # documentation → docs/*.md
python3 scripts/verify.py --build  # renderer coverage · schema · collisions · web build
```

`verify.py` enforces the contracts that are easy to break silently: every event kind must have
a renderer in both the PIL compositor and the React player, every box must be inside the
normalised stage, no two same-corner graphics may overlap for more than 1.2 s, and
`web/src/data/timeline.json` must match `graphics/timeline.json` byte for byte.

## The web player

`web/` is a production-shaped Vite + React 18 + TypeScript app. Drop in any video, and the
overlay layer syncs to it.

**Sync engine.** `useVideoClock` interpolates the playhead on `requestAnimationFrame`, anchored
by `requestVideoFrameCallback` where available with an 80 ms drift guard against the element.
`useActiveEvents` is the timestamp trigger: it only calls `setState` when the *set* of active
beats changes, so a 60 fps playhead never re-renders the tree. Counters write `textContent`
directly; every animated node is transform/opacity only.

**Components** (`web/src/overlay/primitives/`) map 1:1 to the renderer's primitives, so the
live version and the burned-in version are the same design:

`IdCard` `Callout` `Stat` `SpeedHud` `Corner` `EndCard` `Leaderboard` `Bars` `Progress` `Gauge`
`Donut` `Quadrant` `Equation` `Bracket` `Ticker` `Ring` `Waveform` (Canvas) `AdBreak` `Chapter`

**Features:** scrub-safe marquees · sync-offset calibration slider (±300 ms) · playback rate
0.5–2× · keyboard transport (`space`, `←/→`, `J/K/L`, `G`) · canvas timeline map with GSAP
playhead · searchable scene index · live telemetry (plate motion / luminance / audio dB) ·
`dg:enter` / `dg:exit` CustomEvents for external sound or analytics · drag-and-drop to re-sync
any video file.

## Notes

- **Binary artefacts are git-ignored** (see `.gitignore`); regenerate with the commands above.
- **Fonts are in-repo system faces** (DejaVu) so renders are deterministic across machines.
- **No licensed media**: the score is synthesised, and the source video is used as-is.
- The full 27-minute burn-in takes ~17–20 min on one vCPU at 720p; the highlights render used
  here is ~8 min at 60 fps.
- The FFmpeg path uses **libass** rather than `drawtext`, because `drawtext` is missing from many
  static FFmpeg builds (including the one in this sandbox). libass also gives vector panels,
  per-event alpha, velocity moves and letter spacing — see `docs/ARCHITECTURE.md`.
